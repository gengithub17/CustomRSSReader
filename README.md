# CustomRSSReader

複数のサイトから「本当に読みたいカテゴリの記事だけ」を集めて表示する、自分専用のRSS集約Webアプリ。

一般的なRSSリーダーはサイト単位でしか購読できず、興味のあるカテゴリ・タグの記事だけを
絞り込むことができない。CustomRSSReaderは、サイトが提供するRSSをリンクのパスや
カテゴリで絞り込んだり、RSSが存在しないサイトのカテゴリ一覧ページを直接スクレイピングする
ことで、「特定サイトの特定カテゴリだけ」を自分専用のフィードとして集約する。

## 仕組み

Web UI(`/sources`)で登録したサイトを一定間隔(デフォルト30分)で巡回し、
サイトごとのルールでフィルタした記事だけをDB(SQLite)に貯め、Web UIで一覧表示する。

対応しているソースタイプ:

- **`rss_link_filter`**: サイトが提供するRSS/Atomフィードを取得し、記事リンクの
  URLパス(`include_path_prefixes`)やカテゴリタグ(`include_categories`)で絞り込む。
  「RSSはあるが、カテゴリ別RSSは無い」サイト向け。
- **`html_listing`**: RSSが存在しない(または使えない)サイト向けに、カテゴリ絞り込み
  済みの一覧ページ自体をスクレイピングする。CSSセレクタで記事カード・タイトル・
  リンク・日付・要約・画像を抜き出す。

ソースの追加・編集・削除・有効/無効切り替えは **すべてWeb UI(`/sources`)から行う**。
設定ファイルは存在せず、コンテナを起動したら`/sources`から読みたいサイトを登録していく
だけでよい(コード変更・ファイル編集・再起動は不要)。ただし `html_listing` はサイトの
HTML構造に依存するため、サイトがリニューアルされるとセレクタの調整が必要になる。
取得が失敗した場合は `/sources` ページでエラー内容を確認できる。

## 要約機能(AIエージェント不使用)

新着記事が見つかると、サーバ側で以下を行う(外部AI API・LLMは一切呼び出さない):

1. 記事本文ページを取得し、`content_selector`で本文を抽出
   (未指定の場合は`<article>`や`class`に`content`/`body`を含む要素から本文らしきものを推定)。
2. 文章を英語/日本語で自動判定し、それぞれに合った方法で文分割・形態素解析(日本語は
   `janome`、英語は簡易ストップワード除去)を行う。
3. **TextRank**(文同士の類似度グラフ+PageRank)で重要な文を3つ抜き出し、DBに保存する。

これはあくまで「原文から重要な文をそのまま抜粋する」抽出型要約であり、LLMのように
言い換えて要約する抽象型要約ではない。記事タイトルの下に重要文が箇条書きで表示されるほか、
「AI要約用にコピー」ボタンで選択した記事(タイトル・重要文・リンク)をクリップボードに
コピーし、ChatGPTやClaudeなど好きなAIチャットに貼り付けて要約・整理してもらうこともできる。
**AI呼び出しは完全にクライアント側(ユーザー自身の操作)で行われ、サーバはAPIキーや料金と
無関係。**

## 記事の検索・絞り込み・一括操作

記事一覧(`/`)では以下を組み合わせて絞り込める:

- **ソース別**: チェックボックスで複数選択可(何もチェックしなければ全ソース対象)
- **表示**: 「未読のみ(デフォルト)」「既読のみ」「ブックマークのみ」「すべて」の4択
- **キーワード検索**: タイトル・RSSの要約・TextRankで抜き出した重要文を対象に部分一致検索
- **期間検索**: 記事の公開日(`published_at`)で開始日・終了日を指定

すべてURLクエリパラメータ(`?source=...&show=...&q=...&date_from=...&date_to=...`、
`source`は複数指定可)に反映されるため、特定の検索条件のURLをブラウザのブックマークに
保存しておくこともできる。「表示中の記事を既読にする」ボタンも、現在の絞り込み条件
(ソース・表示・キーワード・期間)の範囲内だけに作用する。

### ブックマーク

各記事の「既読にする」ボタンの横に「ブックマークする」ボタンがあり、既読/未読の状態とは
独立してON/OFFできる(既読にしても消えない、後で読み返したい記事の目印用)。上部の
固定ツールバーから選択中の記事へまとめてブックマークを付ける/外すことも可能。
表示フィルタで「ブックマークのみ」を選ぶと、既読・未読を問わずブックマーク済みの記事だけが
一覧に並ぶ。

記事ごとにチェックボックスがあり、複数選択して以下を一括実行できる:
「既読にする」「未読にする」「新しいタブで開く」「AI要約用にコピー」(全選択チェックボックス
あり)。個別の記事にも既読⇔未読を切り替えるボタンがある(既読記事も再度未読に戻せる)。

## ローカルでの起動

```bash
docker compose up -d --build
```

起動後 `http://<ホスト>:8000/` で記事一覧、`http://<ホスト>:8000/sources` で
ソースの追加・管理・取得状況の確認ができる。

> **Windows + クラウド同期ドライブ(Google ドライブ等)配下で試す場合の注意**
> プロジェクトをクラウド同期の仮想ドライブ配下(例: `G:\マイドライブ\...`)に置いていると、
> Docker Desktopのbind mount(`./data`)がホスト側のファイルを正しく反映しないことが
> ある(仮想ドライブ特有の制限)。その場合はローカルディスク(`C:\`など)にプロジェクトを
> 置くか、実ファイルシステム上のLinux環境(後述のデプロイ先など)で実行するとよい。

## デプロイ(Raspberry Piなど常時稼働させたいDockerホスト)

1. Docker / Docker Compose をインストール(Linux 64bit推奨)。
   ```bash
   curl -fsSL https://get.docker.com | sh
   sudo usermod -aG docker $USER
   sudo apt-get install -y docker-compose-plugin
   ```
2. このプロジェクト一式を配置する(`git clone` や `scp` など)。
3. 起動:
   ```bash
   cd CustomRSSReader
   docker compose up -d --build
   ```
4. `http://<ホストのIP>:8000/` にブラウザでアクセスし、`/sources` から
   読みたいサイトを登録する。
5. `docker-compose.yml` の `restart: unless-stopped` により、ホストの
   Dockerデーモンが立ち上がれば自動的にコンテナも起動する。

データは `./data/customrss.db`(SQLite)に保存されるため、コンテナを再ビルド・再作成
しても記事や既読状態は消えない。

## 新しいソースの追加方法(Web UI)

`/sources` → 「+ 新しいソースを追加」から、以下を入力してソースを作成できる。
保存前に「この設定でテスト取得」ボタンで実際に何件マッチするか確認できるので、
CSSセレクタやパスの調整を試行錯誤しながら行える。既存ソースも「編集」から
同じ画面でいつでも調整可能(ソース名は作成後変更不可)。

設定ファイルは存在しないため、以下はあくまで「UIのどのフィールドに何を入力するか」を
YAML風の記法でまとめた参考例(実際にyamlファイルへ書き込むわけではない)。

### 例1: RSSはあるがカテゴリ別RSSが無いサイト

まず対象サイトの `/some-category/` のようなカテゴリ一覧ページで、実際に載っている
記事のURLパスがどんな規則か確認する。多くのサイトでは記事URL自体に
`/category-slug/`のようなカテゴリスラッグが含まれているので、それをそのまま
`include_path_prefixes` に指定すればよい(RSS内の`<category>`タグは、URL上の
分類と一致しないことがあるため注意)。

```yaml
- name: "サイト名 - カテゴリ名"
  type: rss_link_filter
  enabled: true
  feed_url: "https://example.com/feed/"
  include_path_prefixes:
    - "/category-slug/"
  base_url: "https://example.com"
  content_selector: ".article-body"  # 省略可。記事本文コンテナのCSSセレクタ(要約用)
```

### 例2: RSSが無いサイト(一覧ページを直接スクレイピング)

対象の一覧ページのHTMLを見て、記事カードのCSSセレクタを特定する
(ブラウザの開発者ツールで「検証」すると早い)。

```yaml
- name: "サイト名 - カテゴリ名"
  type: html_listing
  enabled: true
  base_url: "https://example.com"
  list_url_template: "https://example.com/blog?category=123&page={page}"
  max_pages: 3
  stop_when_no_new_items: true
  content_selector: ".article-body"  # 省略可。記事本文コンテナのCSSセレクタ(要約用)
  selectors:
    item: "article.card"          # 記事カード1件を囲む要素
    link: "h2 a"                  # 記事へのリンク
    title: "h2 a"                 # タイトル
    date: ".date span"            # 日付テキスト(省略可)
    date_format: "%B %d, %Y"      # strptime形式(省略可)
    summary: ".summary"           # 要約(省略可)
    image: ".thumbnail img"       # サムネイル画像(省略可)
```

## 環境変数

`docker-compose.yml` で上書き可能:

- `FETCH_INTERVAL_MINUTES` (デフォルト30): 巡回間隔(分)
- `DB_PATH` (デフォルト`/app/data/customrss.db`)
- `CUSTOMRSS_USER_AGENT`: スクレイピング時に送信するUser-Agent

## 既知の制約

- `html_listing` タイプはサイトのHTML構造に強く依存する。サイトリニューアルで
  壊れた場合は `/sources` ページのエラー表示で気づけるので、セレクタを
  UI(`/sources` → 編集)側で更新する。
- ソース名(`name`)は作成後に変更できない。記事は`source_name`文字列で紐づいており、
  ソースを削除しても取得済みの記事自体は残る(ただし以後の更新は止まる)。
- DBスキーマにカラムを追加した場合、起動時に`app/db.py`の`_COLUMN_MIGRATIONS`にある
  差分だけを自動で`ALTER TABLE`する簡易マイグレーションが働くため、既存の
  `data/customrss.db`を消さなくてもアップデートを反映できる。
- 巡回対象サイトの利用規約・robots.txtの範囲内で利用すること。取得間隔を極端に
  短くしない(デフォルト30分を推奨)。
